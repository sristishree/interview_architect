# Deployment Design — Interview Architect

**Date:** 2026-08-24
**Status:** Approved (resolved via grill-me session)
**Branch:** `knowledgebase_enrichment` → merge to `master` before deploying

---

## 1. Goals

Deploy Interview Architect as a publicly accessible portfolio app at minimal fixed cost. Two guiding constraints:

1. **Free tier wherever possible** — every service used must have a permanent free tier with no credit card required, or be free for the traffic levels expected at this point.
2. **Keep the LangGraph Server** — the multi-agent pipeline stays as a separate LangGraph process; it is not collapsed into FastAPI.

---

## 2. Architecture Overview

```
User browser
    │
    ▼
Cloudflare Pages  (React SPA)
    │  VITE_API_BASE_URL
    ▼
Render — FastAPI service          (interview-architect-api.onrender.com)
    │  LANGGRAPH_URL
    ▼
Render — LangGraph Server service (interview-architect-langgraph.onrender.com)
    │  OPENROUTER_API_KEY → OpenRouter API
    │  DATABASE_URL       → Neon.tech Postgres
    │  REDIS_URI          → Upstash Redis
    ▼
(shared) Neon.tech Postgres  ← also used by FastAPI for session history
```

**Two Render free services, one Neon DB, one Upstash Redis.**

## 4. Code Changes Required

Changes are listed in implementation order (each step unblocks the next).

### 4.1 Remove PaddleOCR

**Files:** `app/agents/text_extractor.py`, `requirements.txt`

- Delete `_ocr_pdf()` function and all PaddleOCR/pymupdf imports.
- If pypdf returns fewer than 100 characters from a PDF, raise a clear error: `"Could not extract text from this PDF. Scanned or image-only PDFs are not supported."`
- Remove from `requirements.txt`: `paddlepaddle`, `paddleocr`, `pymupdf`.

### 4.2 Split requirements.txt

Create `requirements-dev.txt` containing dependencies only needed for ingestion scripts and development:

```
sentence-transformers>=2.7.0
kagglehub>=0.3.0
beautifulsoup4>=4.12.0
requests>=2.31.0
pytest>=8.0.0
pytest-asyncio>=0.23.0
-r requirements.txt
```

Production `requirements.txt` retains only what's needed at runtime (agents, API, graph, DB).

### 4.3 Migrate Session Store to Postgres

**File:** `app/db/store.py`

- Replace `create_engine(f"sqlite:///{path}")` with `create_engine(os.environ["DATABASE_URL"])`.
- Remove `_migrate()` entirely — Postgres is the target from day one; `Base.metadata.create_all(engine)` handles table creation.
- `_DEFAULT_DB_PATH` parameter removed; `SessionStore()` takes no args (reads `DATABASE_URL` from env).
- SQLite partial index syntax in `_migrate()` (`WHERE thread_id IS NOT NULL`) is SQLite-specific — this is removed along with `_migrate()`.

### 4.4 Add /health Endpoint

**File:** `api/main.py`

```python
@app.get("/health")
async def health():
    return {"status": "ok"}
```

Used by: Render health checks, and the cold start UX ping from the frontend.

### 4.5 Add Rate Limiting

**File:** `api/routes/interview.py` (or a new `api/middleware/rate_limit.py`)

In-memory counter per IP:
- 3 runs per IP per day (rolling 24h window, reset at UTC midnight is also acceptable)
- 1 concurrent run per IP at a time
- Bypass: `X-Admin-Token: <ADMIN_TOKEN>` header skips both limits

Rate limit errors return HTTP 429 with a human-readable message:
- `"Rate limit: 3 runs per day per IP reached."`
- `"Rate limit: only 1 concurrent run per IP."`

In-memory means limits reset on Render restart (cold start). Acceptable for a demo app.

### 4.6 Cold Start UX

**File:** `ui/src/App.jsx` (or a new `ui/src/hooks/useWarmup.js`)

Two-signal approach:

1. **Proactive ping on page load:** On mount, `GET /health`. If response takes > 2 seconds (or fails), show a warm-up banner: *"The server is waking up — first run may take 30–60 seconds longer than usual."* Hide the banner once `/health` responds successfully.

2. **Reactive banner during SSE:** If 10 seconds pass with no SSE progress event after submission, show a secondary banner: *"Still warming up… hang tight."* Hide it on the first progress event.

Neither banner blocks the submit button. The user can submit immediately; the banners are purely informational.

### 4.7 History Access — Admin-Only Auth

**Scope:** Session history (`GET /sessions`) is only meaningful to the app owner. Anonymous visitors can generate interviews but cannot browse history.

**Mechanism:** HTTP Basic Auth on the `/sessions` routes, validated against a single hardcoded admin credential stored as a Render secret. No user table, no JWT, no session cookies.

**Files:** `api/routes/sessions.py`, `api/main.py`

```python
import secrets
from fastapi import Depends, HTTPException, status
from fastapi.security import HTTPBasic, HTTPBasicCredentials

security = HTTPBasic()
ADMIN_USER = os.getenv("ADMIN_USER", "admin")
ADMIN_PASSWORD = os.getenv("ADMIN_PASSWORD")

def require_admin(credentials: HTTPBasicCredentials = Depends(security)):
    ok = (
        secrets.compare_digest(credentials.username.encode(), ADMIN_USER.encode())
        and secrets.compare_digest(credentials.password.encode(), ADMIN_PASSWORD.encode())
    )
    if not ok:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            headers={"WWW-Authenticate": "Basic"},
        )
```

Apply `Depends(require_admin)` to:
- `GET /sessions` — list all sessions
- `GET /sessions/{session_id}` — session detail
- `GET /sessions/{session_id}/resume` — original resume file

The generate flow (`POST /interview`, SSE stream) remains open to all visitors.

**Frontend:** The History page sends credentials via the `Authorization: Basic ...` header. Credentials are stored in `localStorage` after a successful login prompt. A simple login screen (username + password fields) guards the History route in the React router.

**Env vars added to FastAPI service:**

| Variable | Description |
|----------|-------------|
| `ADMIN_USER` | Admin username (default: `admin`) |
| `ADMIN_PASSWORD` | Admin password (set as Render secret) |

**Future — Option B (multi-tenant auth):** When the app opens to public users who want their own history, replace this with a proper auth subsystem: user registration, OAuth (Google/GitHub), JWT tokens, and a `user_id` foreign key on `interview_sessions`. Each user sees only their own rows. The `/sessions` routes gain a `current_user` dependency that scopes all queries by `user_id`. This is deferred to a follow-up milestone.

### 4.8 CORS Configuration

**File:** `api/main.py`

```python
from fastapi.middleware.cors import CORSMiddleware

ALLOWED_ORIGINS = os.getenv(
    "CORS_ALLOWED_ORIGINS",
    "https://interview-architect.pages.dev"
).split(",")

app.add_middleware(
    CORSMiddleware,
    allow_origins=ALLOWED_ORIGINS,
    allow_methods=["GET", "POST", "DELETE"],
    allow_headers=["*"],
)
```

Local dev: set `CORS_ALLOWED_ORIGINS=http://localhost:5173` in `.env`.

### 4.9 FastAPI Dockerfile

New file `Dockerfile.api`:

```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["uvicorn", "api.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

Port is overridden by Render's `$PORT` env var — pass `--port $PORT` or let uvicorn read it.

### 4.10 LangGraph Dockerfile

Run once locally:

```bash
langgraph dockerfile Dockerfile.langgraph
```

This reads `langgraph.json` and generates a self-contained Dockerfile. Commit the generated file. Do not run `langgraph up` on Render — it requires Docker Compose.

## 6. What Is Removed

| Removed | Reason |
|---------|--------|
| LiteLLM proxy | Direct OpenRouter is simpler; `config.py` already uses `OPENROUTER_*` |
| PaddleOCR + paddlepaddle + pymupdf | Scanned PDF support dropped; reduces image size significantly |
| SQLite + backup strategy | Neon Postgres handles durability; ephemeral disk on Render is unreliable |
| `_migrate()` function | SQLite-specific; not needed with Postgres |
| sentence-transformers (production) | Runtime only uses `difflib`; sentence-transformers is ingestion-only |

---

## 7. Deployment Sequence

1. Make all code changes (§4.1 → §4.10) on a feature branch.
2. Provision Neon.tech DB — copy connection string.
3. Provision Upstash Redis — copy `rediss://` URI.
4. Generate LangGraph Dockerfile locally: `langgraph dockerfile Dockerfile.langgraph`.
5. Deploy LangGraph service to Render (Docker); set all LangGraph env vars.
6. Deploy FastAPI service to Render (Docker); set all FastAPI env vars including `LANGGRAPH_URL` from step 5.
7. Deploy frontend to Cloudflare Pages; set `VITE_API_BASE_URL` from step 6.
8. Smoke test: upload a resume, confirm SSE stream, confirm session appears in history.

## 8. Deferred

- **Multi-tenant auth (Option B):** Documented in §4.7. User registration, OAuth, JWT, per-user session scoping. Deferred to a follow-up milestone after launch.
- **BYOK (Bring Your Own Key):** Users supply their own OpenRouter key. Integration point: LangGraph `RunnableConfig` with `configurable.user_api_key`. Deferred to post-launch follow-up.
- **Custom domain:** Free Cloudflare Pages and Render URLs are used for launch. Custom domain adds no cost on Cloudflare but requires DNS management.
- **Database migrations tool (Alembic):** Not needed at launch since Postgres is greenfield. Add if schema changes are needed post-launch.
